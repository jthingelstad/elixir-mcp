# 2026-11-02 — The `elixir-mcp` CloudWatch dashboard is retired

Jamie, 2026-11-02: "Approved: delete the CloudWatch dashboards
yvn-release-notes, elixir-mcp and elixir-drop-operations from their
product stacks now that Grafana has their panels".

**What.** `OpsDashboard` (`elixir-mcp`, added 2026-10-09) is gone from
`infra/template.yaml`, so the stack update deletes it. It had no output
and nothing referenced it. `infra-controls.test.mjs` now holds the
template free of any `AWS::CloudWatch::Dashboard`, in place of the check
that kept the dashboard under 50 metrics.

**Where the panels went.** Grafana on Otto (`otto-ops`, generated by
`scripts/build_grafana_dashboards.py`): the Elixir dashboard carries the
operations panels (the doors and their throttles, recording and the job
ledger, the database, mail, CloudFront and the MCP log's tool tables),
and Elixir product shows use. Grafana reads the same CloudWatch metrics
and log groups, so every alarm, custom metric, metric filter and log
group stays exactly as it was. The one panel with no Grafana equivalent
is the alarm list: Grafana's CloudWatch plugin has no alarm panel, and
the alarms already reach Discord and the morning digest through
`projects-ops-alerts`.

**The decision.** "Dashboards live in Grafana on Otto and add no
metrics" replaces "One dashboard, `elixir-mcp`, adds no metrics" in
`docs/DECISIONS.md`. The no-metrics half stands; the 50-metric free-tier
bound left with the dashboard.

MCP and JSON API unchanged; no migration. Nothing a tool serves changed,
so the deploy runs no acceptance family; the read-back is
`aws cloudwatch list-dashboards` without `elixir-mcp` and the 25
`elixir-mcp-*` alarms unchanged.

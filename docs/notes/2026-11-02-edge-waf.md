# 2026-11-02 — The distribution carries the shared edge web ACL

Jamie, 2026-11-02: "Approved: build one shared AWS WAF web ACL in count
mode in projects-sysadmin and attach it to all 22 CloudFront
distributions through their stacks".

**What.** `SiteDistribution` sets `WebACLId: !ImportValue
edge-waf-WebAclArn`, the web ACL named `edge` that projects-sysadmin's
`edge-waf` stack owns and exports. Every rule in it is in count mode, so
nothing is blocked: requests are only counted and sampled. The stack
owns no WAF resource of its own; `infra-controls.test.mjs` holds both.

**Why it is safe to deploy.** Only the distribution's config changes, in
place. CloudFront reads the web ACL as the caller of the update
(`wafv2:GetWebACL`), and the deploy runs as cloud-engineer, which has
it. The import also means the `edge-waf` stack cannot drop or rename the
export while this stack uses it.

**The decision.** "The edge carries the shared `edge` web ACL" joins
`docs/DECISIONS.md`, and WAF leaves the declined line it shared with
RDS Proxy and Performance Insights.

MCP and JSON API unchanged; no migration. Nothing a tool serves changed,
so the deploy runs no acceptance family; the read-back is the
distribution's `WebACLId` and the site, OAuth metadata and MCP door
answering as before.

# 2026-11-09 — A first-use funnel read

Nothing answered "of the people who made an account, how many added a
player, got a first read and came back?". `{stats}` counts tables and
`{"account_role": {"list": true}}` lists accounts; the numbers were
counted by hand. The new migrate op `{funnel}`
(`services/migrate/src/ops-funnel.mjs`) answers it as counts, in a
read-only session, overall and by the UTC week the account was made.

- **Population.** Person accounts made in the last `days` (default 90).
  Agents and integrations are principals, not people, and are left out.
- **First read** is not a second definition: it is the rule
  `GET /api/me/first-answer` and Home already use, a profile snapshot or
  battle evidence (`hasBattleEvidence`, `@elixir-mcp/record/capture-state`)
  for the primary tag.
- **Signed in** is any trace a sign-in leaves: a `signed_in` event (the
  web code and Discord), a session row, an OAuth family (consent by code
  signs in without the event) or a call of the person's own. Session rows
  go 30 days after they expire, so an old sign-in made only through OAuth
  consent is still seen through its family. `enrolled_never_signed_in`
  counts `{account_enroll}` accounts with none of these.
- **Came back** follows the beta pulse's rule (Jamie, 2026-10-08): a
  sign-in or an own call on a later day, never a session merely seen or
  refreshed. Here the day is UTC, within 7 and 30 days of the day the
  account was made.
- **Time to first read** runs from the primary claim's creation to the
  earlier of the first admitted profile receipt's fetch and the first
  battle row stored for the tag. A primary Elixir already held before it
  was claimed (another account records it, or it was an opponent) has no
  wait and is counted as `already_recorded`.
- **Agent connected** is a live OAuth family that is not a family app's
  sign-in (Drop, Clan), or an unrevoked MCP service token, on the person
  or an agent they own. [engineering]

No figure needed `null`: each step has a recorded source. The op is a
read on `npm run op`'s allowlist and has its row in the ops catalogue.
No contract, API or migration change.

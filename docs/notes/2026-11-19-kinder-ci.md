# 2026-11-19 — A kinder CI: main's push run tests only what is left

Jamie asked for elixir-mcp's CI to be kinder (2026-11-19). In November it
was about 59% of all Actions minutes on Jamie's account, about 21,300
minutes by the 19th, and up to 5,400 in one day. The repository is public, so
the minutes are free; the ask is to spend less of GitHub's compute without
testing less.

## Where the minutes went

From 11-12 to 11-19 validate ran 938 times: 569 for pull requests and 369
for pushes to main (about fifty merges a day). In a sample of about 120 runs
the journeys were 55% of the minutes, the test shards 32%, and every push
to main ran the full workflow, journeys included, again after its pull
request had passed. Of 60 merges sampled, 24 left main with exactly the
tree their pull request head had already tested.

## What changed

The `changes` job asks `infra/scripts/push-plan.mjs` (`lib/push-plan.mjs`)
on a push to main:

- **Already tested.** When the deploy gate (`lib/ci-gate.mjs`) would pass
  HEAD as it is, because a merged pull request head with HEAD's tree has a
  green `validate`, `static`, the test shards and the journeys are skipped,
  and `validate` passes on the `changes` job alone, holding the other jobs
  to `skipped`.
- **Otherwise** everything runs, and the journeys run when what changed
  since main's newest commit with a green `validate` reaches them
  (`e2e-needed.sh`, the pull requests' own rule). The baseline is not the
  previous commit: GitHub cancels a queued main run when a newer one
  queues, so that commit may never have been tested.
- Any doubt (an API error, no green commit in the last 30) runs it all.

The job gains `pull-requests: read` and `checks: read`, the reads the deploy
gate makes. Pull requests are unchanged. No contract change: MCP and the JSON
API keep their versions. `services/mcp/test/push-plan.test.mjs` drives each
branch offline.
